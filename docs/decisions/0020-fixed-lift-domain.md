# 0020 — Fixed lifting uses level-hygienic list construction

- **Status:** accepted
- **Date:** 2026-08-23
- **Task:** 3.3
- **Amends:** 0009 (Reflection now also contains `lift`) and 0019 (primitive callbacks)

## Context

Task 3.3 fixes the values that may cross from the static value domain into Code:
scalars, unit, recursively liftable immutable lists, and Code itself. Everything
carrying executable behavior, identity, mutable state, or runtime context must be
rejected. Two details were not yet fixed by the design: how a non-empty list can
be expressed as hygienic Core when no list literal exists, and how a nested
rejection can name the offending value's origin when runtime values do not all
carry source spans.

The primitive registry cannot choose a list binder when it is constructed.
`Primitives.globals` deliberately allocates new hygienic identities for every
level, while primitive values are shared. Generating `NamedVar("list")` would
avoid that dependency but turn ordinary lifted data into reflective name lookup,
contradicting the purpose of hygienic globals and leaving avoidable reflection in
future residual programs.

## Decision

**`lift` is an exhaustive whitelist.** Numbers, booleans, strings, symbols, and
unit become `Lit`; the empty list becomes `Lit nil`; a non-empty immutable list
becomes an application of the current level's exact `list` global to recursively
lifted items. Existing Code passes through unchanged, including its identity,
spans, and generated provenance. This makes Code inside a list a dynamic element
expression rather than Code quoted as a runtime Code value.

Closures, reifiers, continuations, environments, cells, and primitives are all
rejected. The last two shapes omitted by spec D6's original table are rejected by
the fixed-domain rule: absence from the whitelist is not permission to serialize
a newly encountered runtime shape. Every match is exhaustive so adding another
value variant forces a new decision.

**The applying evaluator supplies a `lift` callback.** `Value.primitive.prim_impl`
receives `~lift` beside `~apply` and `~run`. The ground callback resolves `list`
in the machine's explicit level-global environment and embeds that exact identity
in generated Core. It never consults the caller's lexical environment and never
generates `NamedVar`. Phase 4 can therefore lift against each materialized
level's cloned globals without rebuilding or mutating the shared registry.

**Generated nodes retain the `lift` call's provenance.** Every scalar and list
node invented by lifting uses a span generated by `lift` from the primitive call
site. A passed-through Code node keeps its existing provenance.

**A rejection carries a data-origin path.** `Error.Unliftable_value` records the
opaque rendering and type phrase of the rejected leaf plus one-based indexes
through every enclosing immutable list. Its ordinary error span is the source
`lift` call. Thus a nested failure names both where the conversion was requested
and which value within the recursive input caused it, instead of only saying
"expected a liftable value, found a closure." The path contains no identities or
allocation-order observations.

**`lift` is Reflection.** Although the Code it produces is immutable, non-empty
list lifting depends on the current evaluator level's global identity and is the
explicit value-to-stage boundary. Like `run`, it therefore receives a bespoke
specialization rule rather than the automatic "all static arguments may fold"
rule for ordinary Pure primitives. The direct-style oracle consequently refuses
it by class, preserving the oracle's no-staging boundary.

## Alternatives

**Generate `NamedVar("list")`.** Rejected because it converts a hygienic,
statically known primitive reference into runtime string resolution and would
pollute later collapse measurements with an avoidable `NamedVar` lookup.

**Capture one list identity in the registry.** Rejected because levels clone
global binders while sharing primitive values. A captured ground identity would
make Code generated at an upper level depend on the wrong environment.

**Add arbitrary lists to `Constant`.** Rejected because it would expand Core's
closed constant domain solely for one staging operation and duplicate the
existing immutable-list primitive semantics.

**Report only the rejected type at the call site.** Rejected because recursive
lifting can discover the bad value arbitrarily deep inside otherwise liftable
data. The path is the origin information available without adding provenance to
every runtime scalar and identity-bearing object.

**Classify `lift` as Pure.** Rejected because the list case is level-dependent
and because the frozen oracle must continue to reject staging. Immutable Code
observation and construction remain Pure; crossing from values into a stage is a
different operation.

## Consequences

- The registry grows from 37 to 38 primitives; Reflection is `lift` and `run`.
- Primitive implementations receive `~apply`, `~lift`, and `~run`; ordinary
  primitives ignore the callbacks they do not use.
- Lifted list Core is closed relative to the active level globals and contains no
  reflective printed-name dependency.
- The value and Core domains do not grow, and closures, contexts, and stores are
  never serialized.
- `Error.Unliftable_value` is a new structured cause that exhaustive consumers
  must handle.

## Test impact

`test/unit/lift_test.ml` covers every scalar, unit, empty and nested lists, Code
identity/provenance, Code nested in a list, exact hygienic list identity, all six
rejected runtime shapes, call-site location, and a nested origin path.
`primitives_test.ml` independently pins `lift`'s Reflection class, arity, and an
accepted argument, while `error_test.ml` pins the structured diagnostic.

## Required spec or measurement changes

Spec D6 now states Code identity, exhaustive rejection, level-hygienic list
construction, generated provenance, and the nested origin-path diagnostic. D7's
Reflection row includes `lift`. No metric definition changes: avoiding generated
`NamedVar` makes the existing named-lookup metric more faithful.
